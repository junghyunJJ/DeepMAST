# 사후 평가 복구 방법과 판정 기준

## 원본과 평가 기준

- 대상: 기존 Guardrail ON 20회, 생성이 끝난 Guardrail OFF 20회. 모두 SNI를 활성화한 BC 데이터 반복 실행이다.
- 보고서 생성, 수정, repair는 실행하지 않았다. 원본 보고서를 새 평가 폴더로 복사하고, 원본과 복사본의 SHA-256을 비교했다.
- 모델은 기존 qwen3.5:122b이며, 준비 시점과 각 평가 시도 전 모델 digest를 비교했다. 근거 컬렉션, 판정 상태의 정의, claim 선택 규칙, 오류의 심각도 규칙을 유지했다.
- 기존 공통 사후 평가의 content-addressed checkpoint 중 정상 완료된 판정과 검색 결과를 재사용했다. 생성 시점 가드레일의 판정 캐시는 사용하지 않았다.

## 복구한 오류

1. **Event loop is closed:** 기존 코드는 한 Ollama 비동기 HTTP 클라이언트를 재사용하면서 각 호출의 이벤트 루프를 종료했다. 동일 클라이언트의 연속 호출에서 성공→RuntimeError→성공을 재현했다. 한 보고서의 평가 동안 하나의 asyncio.Runner를 유지하여 해결했고, 실제 모델 연속 4회 호출 및 실제 첫 ON 보고서로 확인했다.
2. **빈/깨진 도구 응답:** 일부 실제 문장에서 function-calling 응답이 잘리거나 XML 형식 오류를 내면서 판정 객체가 None이 됐다. 같은 근거·분류 지침·Pydantic 판정 스키마를 이용한 JSON 응답으로 복구했다. 응답 형식 지시만 명시적으로 덧붙였으며, 판정 범주나 합격선을 바꾸지 않았다. 이 경로는 관측된 형식 오류에만 적용한다. 이미 동일 요청의 형식 실패가 기록돼 있으면 그 복구 경로를 바로 사용한다.

최종 복구 경로는 기존 3,000-token 상한과 남은 호출 시간 제한을 사용한다. JSON이 없거나 끝까지 생성되지 않은 경우에는 판정을 성공으로 처리하지 않는다. 연결 오류 등 다른 예외도 결과로 변환하지 않는다. 과거 오류와 재시도는 각 working copy의 judge_errors.jsonl 및 assessment 기록에 남는다.

## 집계 기준

- 필수 보고서가 없으면 주 지표 불합격.
- 확인된 내용 hard error가 하나라도 있으면 주 지표 불합격. 다른 검사 완료 여부는 별도로 보존한다.
- 내용 오류가 발견되지 않았더라도 필요한 검사가 끝나지 않으면 미확정.
- 필요한 검사가 끝났고 hard error가 0개이면 합격.
- deterministic 검사에서 이미 불합격이 확정되면 추가 의미 검사를 생략한다. 이때 알려진 오류 수는 최소치이며, 미수행 검사를 오류 0개로 간주하지 않는다.
- 오류 때문에 최종 HTML이 생성되지 않은 ON 2건은 출력 차단으로 기록한다. HTML이 이미 생성된 OFF의 missing RAG audit 표시는 출력 차단이 아니다.

최종 비교는 각 arm의 20회 전체를 분모로 사용한다. 교정 카운터는 단계별 검출·수정 작업 횟수이며, 고유한 오류나 수정 문장의 수로 해석하지 않는다. 별도의 독립 과학적 정확성 평가는 포함하지 않는다.

## 검증

- 이벤트 루프 유지, timeout 후 재사용, 오류 상태 분리, 원본/복사본 변조 감지, 형식 복구, 잘린 JSON 거부, 집계 분모에 대한 회귀 테스트.
- 실제 모델에서 실패 요청과 수정 경로 비교.
- 원본 및 복사본 보고서 해시 검증.
- 원본 생성 파이프라인의 코드와 결과는 그대로 보존.
